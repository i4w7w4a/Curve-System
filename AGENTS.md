# Работа над Curve System

Curve System — самостоятельный проект об изменении величин во времени. Основной язык документации — русский; идентификаторы, имена файлов и API — английские. Сначала читать `README.md`, затем релевантный раздел `docs/` и `skills/curve-system/SKILL.md`.

## Контракты

- Различать значение `f(t)`, производную по нормализованному времени, физическую скорость, её модуль и пространственную траекторию.
- Сохранять идентификаторы опубликованных кривых. Изменение формулы или семантики требует явной записи в `CHANGELOG.md` и решения о версии данных.
- Не обрезать overshoot без запроса. Не выдавать пружину с искусственно нормированным концом за физический ответ системы.
- Не заменять вычисление cubic Bézier выражением `y(t)`: сначала находить `u`, для которого `x(u) = t`.
- Возвращать `null` для отсутствующей/неопределённой производной по контракту ядра; не изображать разрыв как конечный гладкий пик.
- Проверять граничные случаи, размерность, конечность результатов, свойства заявленного семейства и поведение на стыках. Тесты должны проверять математические свойства, а не повторять реализацию.

## Файлы и воспроизводимость

- `src/curves.mjs` — источник вычисления; `catalog/curves.json`, SVG и каталог документации должны соответствовать ему.
- Изменять генерируемые материалы через `scripts/render-atlas.mjs`, затем запускать `npm run build:atlas` и `npm run check`.
- Графики рисовать программно по фактическому evaluator. Генеративные изображения не использовать для точных графиков.
- Хранить реализацию без обязательных runtime-зависимостей. Новую зависимость добавлять только с конкретной потребностью.
- Не выдавать планы за готовую интеграцию: статусы `implemented`, `reference`, `proposed`, `unverified` должны соответствовать фактам.
- Не добавлять результаты ранее запущенных внешних исследований, если их текст не получен. Авторский обзор и внешний отчёт — разные источники.

## Исследования и происхождение

- Для технических утверждений давать первоисточники; для лицензий проверять файл лицензии нужной версии.
- Сохранять дату проверки, URL и, при импорте внешнего кода, commit/tag и copyright notice.
- Не копировать чужую реализацию, рисунки и текст без проверки условий. Собственные графики производить из собственных формул/кода.
- Habr, X и подборки использовать как слой обнаружения; спецификации, статьи авторов и исходники — для проверки.

## Публикация

Не перезаписывать независимые изменения. Перед обновлением удалённой ветки проверять её текущую вершину. Не использовать force-push. Не публиковать токены и личные файлы. Выбор общей лицензии проекта относится к владельцу; `UNLICENSED` не означает, что права на сторонние проекты отсутствуют.
